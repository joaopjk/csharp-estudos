# Solid
É um conjunto de 5 princípios fundamentais para o design de software orientado a objetos. Eles ajudam a criar sistemas fléxiveis, fáceis de manter, testar e evoluir
- Single Responsibility Principle: Uma classe deve ter apenas uma responsabilidade.
- Open/Closed Principle: Classes devem ser abertas para extensão, mas fechadas para modificações. Novos comportamentos devem ser adicionados sem alterar o código existente.
- Liskov Substitution Principle: Subtipos devem ser substituíveis por seus tipos-base sem causar erros ou alterar o comportamento esperado.
- Interface Segregation Principle: Prefira várias interfaces pequenas e especifícas a uma interface grande e genérica. Classes devem implementar apenas o que realmente usam
- Dependency Inversion Principle: Dependa de abstrações (interfaces ou classes abstratas), não de implementações concretas. Use injeção de dependência para fornecer as implmentações.
